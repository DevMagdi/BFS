# BusinessFlow AI — Technical Baseline Proposal

- **Status:** Technical recommendation for owner review; it remains **not owner-approved**. Some component categories now appear in a separately task-authorized backend baseline; see [`BACKEND_IMPLEMENTATION.md`](BACKEND_IMPLEMENTATION.md) for the actual versions/ranges, runtime choices, limits, and test evidence. This proposal's exact versions are not an approved lock or an integrated-stack claim.
- **Evidence date:** 2026-11-21 UTC. Stable package/release metadata was checked through PyPI, npm registry, and GitHub. At the time of that review, no BusinessFlow baseline dependency had been installed or added; the earlier temporary Gateway test install is recorded in `OPEN_SOURCE_INVENTORY.md`.
- **Scope:** Recommended initial component versions, compatibility, license observations, operations, alternatives, and open approvals.

The later limited implementation does not approve the product or adopt the choices in this proposal wholesale. In particular, the current backend uses a task-scoped synchronous FastAPI/SQLAlchemy/PostgreSQL setup; it does not implement the proposed Keycloak/OIDC integration, frontend, outbox/worker, or storage adapter.

The owner-confirmed product directions remain unchanged: self-hosted/on-prem first with future cloud portability; separate `Tenant` and `Company` with exactly one Company per Tenant in the MVP; first-party authentication plus OIDC/enterprise SSO, MFA, account linking/recovery, session management, and authorization. None of those directions approves the specific products or versions below.

## Compatibility and versioning limits

The versions above are review-date stable registry/release observations, **not an approved lockfile**. Registry dependency constraints support the stated Python/Node combinations at metadata level. No BusinessFlow baseline install, build, vulnerability scan, license scan, integration test, container startup or production run was performed; the earlier external Gateway suite is unrelated and documented in `OPEN_SOURCE_INVENTORY.md`. FastAPI/Starlette/Pydantic, SQLAlchemy/Alembic/psycopg, Next/React/TypeScript, Keycloak/Authlib, and Compose/Engine must be resolved and tested together in CI before this proposal can be accepted. Pin exact artifacts and hashes, review transitive dependencies and produce an SBOM when implementation is authorized.

## Alternatives considered

- **Django/DRF:** mature integrated admin and auth, but more framework surface and a shift from the existing FastAPI proposal; reconsider if first-party product administration dominates the application.
- **Node backend:** could share TypeScript with Next.js, but requires replacing the existing Python/FastAPI proposal and revalidating PostgreSQL/RLS libraries; no current evidence justifies the switch.
- **Database-per-tenant:** stronger physical separation option for future customers, but operationally heavier and not required by the confirmed MVP model; installation topology remains open.
- **DuckDB/Polars:** benchmark later for file/batch analytics; neither replaces PostgreSQL or canonical facts.
- **Redis/Celery/Temporal:** not justified for the first internal action; add only if outbox limits are demonstrated.
- **Cloud object storage/MinIO:** defer; local storage adapter is simpler for the self-hosted first slice, but at-rest encryption, backup and operator responsibilities remain a gate.
- **Django/Keycloak or customer-managed identity:** identity alternatives remain open; the Keycloak recommendation reduces the temptation to write password/MFA/OIDC primitives in the product but adds operational burden.
