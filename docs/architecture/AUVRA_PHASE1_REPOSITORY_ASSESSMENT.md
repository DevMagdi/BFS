## Current-branch Operations implementation and local validation

1. `models.py` defines Company/source-scoped event streams, append-only event versions, a current-version/time projection, and immutable analysis-run snapshots with hashes, actor/source-profile references, and canonical revision links.
2. `schemas.py` separates `manual_assertion` from `canonical_record_revision`, requires timezone-aware timestamps, and constrains corrections and request fields. `engine.py` counts exact source labels in a bounded snapshot and labels authority, completeness, freshness, accuracy, hypothesis, forecast, recommendation, and human decision as unassessed/not produced.
3. `service.py` implements source profile checks, shared source advisory locking, idempotency, hash-linked correction versions, exact same-source operational-record evidence, current-version/time-filtered analysis, saved input/result hashes, replay, and paginated evidence. It batch-verifies each selected event's complete contiguous correction chain, predecessor links, current version and pointer timestamp, and batches version reads to avoid per-event verification queries. History reads lock the current pointer before pagination/verification to avoid a concurrent-correction race. Tests cover ancestor/pointer tampering, concurrent corrections, pointer-lock ordering, and a bounded version-query count.
4. `operations_intelligence_routes.py` exposes event creation/list/detail/history/correction and analysis create/get/evidence endpoints. `main.py` includes the router; `migrations/env.py` registers model metadata. Owner/admin access and member denial are exercised by the local API tests.
5. Migration `0029` declares `0028_universal_data_retention` as parent and upgrades successfully. Final-tree `alembic check` reports no new upgrade operations. PostgreSQL tests confirm forced RLS, scope/grant behavior, linked-revision deletion restriction, and retained-evidence downgrade refusal. The current pointer is trigger-maintained; runtime may update only its two projection columns, and a database guard rejects a pointer whose version or occurrence timestamp is not the latest version.
6. The analysis insert guard checks runtime actor/scope, calculation version, saved scope/period/event count, result count/status, and source revocation. Service-created snapshots pass through it in the API integration tests.
7. Final-tree local verification recorded in [`PHASE1_ACCEPTANCE_REPORT.md`](PHASE1_ACCEPTANCE_REPORT.md): 475 PostgreSQL-backed tests passed; the latest focused Operations set passed 17; Ruff format/lint, mypy, Alembic parity, and final `git diff --check` passed. The focused implementation/security review is complete for this repository diff. Current-branch GitHub CI remains pending; this is not a complete threat model or production security review.

## Reuse decisions

- **Reuse directly:** existing Tenant/Company authorization, transaction-local context, forced RLS, runtime/migrator split, `metrics.snapshot.content_hash`, and bounded replay patterns.
- **Adapt:** Universal Data source profiles and exact revisions as source-scoped evidence; existing canonical activity/operational record types; current BI and M7 patterns only where they fit. These do not prove source authority or Operations semantics.
- **Implement BFS-native:** typed Operations event/version/run records and bounded deterministic observations, within the accepted Phase 1 scope.
