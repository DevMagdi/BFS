## 2. Partial capabilities and limits

## 5. Missing foundations / decision blockers

These are business, source and governance foundations, not problems that can be closed with more code or passing tests alone:

1. A named user, repeated decision/question, domain owner, product scope, decision authority and acceptance baseline for a company-wide business-intelligence capability.
2. Finance/accounting owner(s), authoritative source(s), production access approval, data classification, and an accountable party for source completeness, correction, freshness and retention.
3. A versioned finance fact/transaction model and explicit distinction between accounting records, management-reporting measures, planning assumptions and cash events.
4. Approved revenue/cost/account definitions, effective dates, recognition/cut-off, period-close/restatement, sign, refund/reversal, cross-period correction, and no-double-count policies.
5. Approved currency/FX source and timestamp, units, precision, rounding/display, tolerances and reconciliation control definitions—with independently governed golden examples.
6. Stable cross-source event identity, idempotent corrections/reversals, source population completeness and an approved path for retaining and replaying admissible evidence.
7. M17-ready chronological historical outcomes and evaluation ownership before any forecast/scoring/model-promotion claim.
8. For AI: a named allowed question, authorized/minimized evidence retrieval, on-prem/local inference design if approved, prompt/data-flow policy, grounded-claim evaluation, abstention thresholds, audit and human-review expectations. No AI is implemented here.
9. For production: approved retention/deletion/legal hold, secret custody/rotation, backup/restore, operations, access review and separate customer-data authorization. Synthetic fixtures are not customer evidence or customer performance.
