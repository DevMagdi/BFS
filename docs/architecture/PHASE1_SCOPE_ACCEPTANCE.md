- **Acceptance boundary:** This record accepts the bounded Phase 1 engineering scope below. It is not customer validation, a business-KPI approval, a complete security audit, production authorization, or approval of any external data source.

## Accepted Phase 1 scope

1. **Keep the product company-wide.** Business, Financial, Operational, and Decision Intelligence remain four first-class company-wide pillars. Operations is the first implementation proof, not the product boundary; domains remain optional.
2. **Prove the shared Intelligence Core through an Operations-first vertical slice.** Reuse BFS Tenant/Company authorization, source lineage, forced PostgreSQL RLS, least-privilege runtime/migrator separation, immutable evidence, correction history, deterministic calculation, saved hashes, replay, and human-owned decision boundaries. Keep the implementation in the existing modular monolith and PostgreSQL.
3. **Deliver the bounded Operations observation lifecycle.** Bind each event to one Company-scoped Universal Data source and source-local event key; distinguish a manual assertion from an exact same-source canonical revision; append corrections with predecessor/hash lineage; calculate only bounded counts over current event versions for an explicit half-open time interval; retain and verify saved input/result snapshots for replay.
4. **Accept one initial technical observation metric.** Count recorded current event observations grouped by exact source-defined event-type and before/after state labels for one source and period. Empty scope is `no_matching_evidence`; no zero-filled groups, interpretation, target, or business verdict is produced. This is accepted as a deterministic engineering observation—not as an approved company KPI, operational SLA, productivity measure, or performance target.
5. **Keep explicit limits.** This scope does not add a UI, AI runtime, live connector, workflow engine, forecast, recommendation, approval policy, external action, new domain, finance policy, new dependency, service, datastore, or background worker. Existing finance, customer-data, and retention controls remain unchanged.

## What this acceptance means

The four-pillar direction and Operations-first sequencing are treated as the authoritative Phase 1 engineering baseline for this delivery. Technical completion is determined only by the evidence in [`PHASE1_ACCEPTANCE_REPORT.md`](PHASE1_ACCEPTANCE_REPORT.md) and the requirement-by-requirement matrix in [`../REQUIREMENTS_TRACEABILITY.md`](../REQUIREMENTS_TRACEABILITY.md). Passing code/tests does not prove customer value, source authority, completeness, accuracy, freshness, or business correctness.

No separate Operations-domain, finance, legal, privacy, or production-data approval is claimed. The policy decisions below remain open; they block the corresponding customer/business/production use, not closure of the bounded technical baseline. No historical checklist is used as a source of Phase 1 requirements or a blocker.
